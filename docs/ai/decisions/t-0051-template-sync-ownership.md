# Decision t-0051 — Template Sync Ownership, Withdrawal and Generated Artifacts

## Status
Accepted

## Triggers

- type: file
- path: `\.claude/\.automation/lib/template-sync-engine\.sh`
- path: `\.claude/\.automation/lib/rebuild-machinery-manifest\.sh`
- path: `\.claude/\.automation/machinery-manifest\.txt`
- path: `\.claude/tools/sync-conformance\.sh`
- path: `\.templatesyncignore`
- keywords: `template sync, machinery manifest, withdrawn file, orphan sweep, templatesyncignore, a1-trigger-index, sync-conformance, child sync`

## Context

`template-sync-engine.sh` copies every tracked template file a child is not
excluded from receiving, and is **add/update-only**. Four consequences of that
design, all found while re-governing the massimo A/B fixture:

**1. Withdrawn files live forever in children.** A file deleted from the
template is never deleted downstream. `branch-guard.sh` was removed from the
template on 2026-03-22 and was still present in markpreston seven months later;
`branch-guard-edit.sh` (removed 2026-03-02), `mode-guard.sh` and
`state-guard.sh` (both 2026-02-26) likewise. Four were inert, but
`innovator.md` and `researcher.md` were not: agents resolve by filename, so
both remained dispatchable agent types in a child long after the template
dropped them. Only decisions had a cleanup path (`t-manifest.txt`, Decision
0022); machinery had none.

**2. A generated, per-repo artifact was shipped as if it were template
content.** `docs/ai/decisions/.a1-trigger-index` is compiled from the decision
files present in one repo. The template's copy indexes the template's
decisions, and every sync overwrote the child's. The A1 gate reads that index
*exclusively* — `pre-commit-gates.sh` falls back to parsing decision files only
when the index is **absent**, which sync guaranteed never happened. So no
child-authored decision could ever trigger A1. markpreston had 22 such
decisions and 111 index entries where a local rebuild produces 143. The
staleness guard only ever warned, and before Decision t-0049 the regenerate
command it recommended was itself a silent no-op returning 1.

**3. Exclusion policy was read from the wrong repo.** The engine read the
*child's* `.templatesyncignore`. A child that does not yet have one therefore
excludes nothing on its first sync, and that sync overwrites its `.gitignore`,
its session logs and its compiled specs wholesale.

**4. The engine could not run outside CI.** `merge_gitignore()` passed a
multi-line value through `awk -v`, a GNU extension; BSD awk rejects it and
emits an empty file, which the old code then `mv`'d over the child's
`.gitignore`. And the branch check used `git branch --show-current` (git
2.22+), which is above the supported floor (AI.md § Tooling Floor); below 2.22
it is not a flag and silently compares garbage. Both are invisible on
`ubuntu-latest` and destructive on a Mac. (Observed at the time on the
operator's then-installed git 2.19.2; the defect is the version assumption, not
that particular version.)

A fifth defect was introduced and caught by the new tests: the first draft of
the sweep read its manifest with `grep -v '^#' | grep -v '^$'`, which exits 1
on a header-only file and, under `set -euo pipefail`, killed the engine before
its own corruption guard could run. That is the same failure mode as Decision
t-0049 — an unguarded pipeline aborting a script far from the point of use.

## Decision

### 1. The template owns the exclusion policy

`_load_syncignore_patterns()` reads `.templatesyncignore` from the **template
ref**, falling back to the child's copy only when the template has none. What
the template ships is the template's decision, and the manifest below is
generated against the same list, so sweep and sync always reason about the
same file set.

### 2. Withdrawal is expressed as a manifest diff, never as absence

`.claude/.automation/machinery-manifest.txt` lists every file sync delivers,
regenerated by `rebuild-machinery-manifest.sh` from the git index (not
`ls-tree HEAD`, so a commit that adds a synced file carries a manifest already
listing it).

The engine snapshots the child's manifest **before** sync overwrites it, then
removes files present in the old manifest and absent from the new one.

**The diff is load-bearing and the naive form is unsafe.** "Delete anything the
template does not ship" would also delete a child's own hooks, agents and git
hooks — massimo's `post-merge`, for one. A child-authored file has never
appeared in any manifest and so can never be a sweep candidate. The sweep
additionally refuses to act on an empty incoming manifest, so a truncated file
cannot cascade into mass deletion.

Children synced before this decision have no previous manifest; the sweep
no-ops on that sync and arms itself for the next. Files already orphaned in a
child are not caught retroactively and must be removed by hand (done for
markpreston in `842327d5` and for the massimo fixture in `7a6841c`).

### 3. Generated per-repo artifacts are rebuilt, not delivered

`docs/ai/decisions/.a1-trigger-index` is excluded from sync, and the engine
rebuilds it in the child after decisions are synced and orphans cleaned, so the
rebuild sees the final decision set. The rebuild helper is resolved from
`REPO_ROOT`, not `SCRIPT_DIR`: `SCRIPT_DIR` is wherever the invoked engine file
lives, and an engine run by absolute path from another checkout would otherwise
rebuild that repo's index instead of the child's.

Any future generated, repo-specific artifact follows the same rule — exclude it
from sync and regenerate it downstream. Shipping one is what silently disabled
A1.

### 4. The engine is portable and tested

No GNU-only awk constructs; `git rev-parse --abbrev-ref HEAD` for branch
detection; `.templatesyncignore` patterns loaded once into an array rather than
re-read per file through a process substitution (that form crashes bash 3.2
with SIGBUS once the loop sits inside a command substitution, and macOS ships
3.2.57); and manifests read with awk rather than chained greps.

`.claude/tools/sync-conformance.sh` builds a real template, child and bare
origin in a sandbox and runs the real engine against them — 23 assertions
covering delivery, exclusion, the `.gitignore` merge, withdrawal, the
corruption guard, the branch guard, and the A1 rebuild. Six of them assert the
safety invariant directly: a child's own hook, agent, decision, git hook and
product code survive a sweep.

Like `gate-conformance.sh`, it is deliberately independent of
`.claude/hooks/tests/`. Do not merge them.

## Consequences

- A template file deletion now propagates, one sync later, to every child.
- Children stop losing A1 enforcement of their own decisions.
- The engine can be run by an operator on macOS without destroying a
  `.gitignore`.
- **`rebuild-machinery-manifest.sh` must be re-run whenever a synced file is
  added or removed.** A stale manifest means a missed cleanup, or a spurious
  one. `--check` fails on staleness and is the guard against forgetting.
- First sync after this lands performs no sweep in any child, by design.

## Amendment 1 (2026-10-22) — Manifest drift is detected, not remembered

**Defect.** The Consequences above said the rebuilder "must be re-run whenever a
synced file is added or removed" and that `--check` "is the guard against
forgetting". Nothing ever ran `--check`, so it guarded nothing. By 2026-10-22 the
tracked manifest was missing 15 files (t-0058..t-0061, `_mechanism-helper.sh`,
`verify-pristine.sh`, `work-preserver.sh`, five test files) and had been noticed
stale only incidentally, twice. Headless sessions made it worse: the rebuilder
sits in `.automation/lib/`, which the headless allowlist did not cover, so an
automation session could not regenerate it even when it knew it should (see
t-0063's note that the manifest was left unregenerated for this reason). A
manual step that the agents responsible cannot perform is a step that gets
skipped. Separately, `--help` did not print help: every argument other than
`--check` fell through to the rebuild and rewrote the tracked file.

**Decision.**

1. **The manifest stays tracked.** It is not purely derived from the *template's*
   point of view: children receive it, and the withdrawn-file sweep works by
   diffing the child's previous copy against the incoming one (§2). An untracked,
   regenerate-on-demand manifest would not reach children and would leave the
   sweep with nothing to diff. What *is* derived is its content, which is why it
   can be checked mechanically against a fresh rebuild.
2. **Drift fails `gate-conformance.sh` and CI.** The `## machinery manifest`
   section runs `rebuild-machinery-manifest.sh --check` against the real repo
   (case: "tracked machinery manifest matches a fresh rebuild"), and
   `gate-conformance.yml` runs the same `--check` as its own step on every
   feature/fix/hotfix/release/experiment push, every `main` push and every PR to
   `main`. The real-repo case runs only when `.claude/repo-mode` says `template`:
   the harness is itself synced to children, whose `git ls-files` includes their
   own files, so the comparison could never come out equal there. `repo-mode` is
   untracked, so CI relies on its own step, and that workflow is excluded from
   sync. The same section proves the check can go red, in a scratch repo (which
   needs no guard): add a tracked file → `--check` exits 1 with the STALE report;
   remove one → exits 1; regenerate → exits 0.
3. **Not refreshed from the A1 path.** A1 reads decision files and is a read-only
   gate; making it rewrite and re-stage a tracked file inside a commit hook would
   mutate the commit being judged and hide the change from the author. A1 already
   treats its own generated index as warn-only for that reason. Detection was
   preferred over a hidden write.
4. **Argument handling is strict.** `--help`/`-h` print usage and exit 0; any
   unknown argument — including an empty string — or more than one argument is a
   usage error (exit 2); neither writes anything. Only a bare invocation rebuilds.
5. **Headless can run it.** `_permission-allowlist.sh` admits exactly
   `bash .claude/.automation/lib/rebuild-machinery-manifest.sh` with at most
   `--check` or `--help`. It is deliberately not a grant for `.automation/lib/`.

6. **A structural cause of drift is removed.** `docs/ai/governance/pristine-evidence/`
   (Decision t-0063) is excluded from sync. One tracked evidence file is added per
   mechanism-change commit, so with it in the manifest every such commit made the
   manifest stale by construction. It is hash-bound to a template commit and
   meaningless in a child — the same class as `criteria-verdicts/`, excluded the
   same way. `t-0063-mechanism-change.yaml` was already tracked and shipped; the sweep
   withdraws it from a child only if a manifest that child previously received
   listed it (t-0063 records that the manifest was not regenerated for that
   commit, so it may not have). If not, it stays as an inert orphan to remove by
   hand — harmless, since nothing reads another repo's evidence.

**Known limit.** Detection is at push/PR time (CI) or whenever the harness is run
locally, not at commit time. A commit that adds a synced file without
regenerating the manifest is caught after it is pushed, not before it is made.
That lag was accepted over putting a write in the commit gate; if it proves too
slow, the next step is a read-only check in `pre-commit-gates.sh` that fails when
staged additions/deletions are not reflected in a staged manifest.

## Alternatives Considered

**Delete anything absent from the template tree.** Simplest, and wrong: it
cannot distinguish a withdrawn template file from a child-authored one, so it
would delete the child's own machinery. Rejected on the safety invariant.

**Extend `t-manifest.txt` to cover machinery.** Conflates two lifecycles.
Decisions are swept by naming convention (`t-` prefix marks template
ownership); machinery has no such marker, which is exactly why it needs the
diff. Kept separate.

**Leave `.a1-trigger-index` synced and rely on the staleness warning.** The
warning was already firing and was already being ignored, and a warning cannot
restore enforcement of a decision the gate cannot see. Rejected.

**Add a full-parse fallback to A1 when a decision is missing from the index.**
Treats the symptom, costs a fork per decision on every commit, and leaves the
index wrong. Rejected in favour of not shipping the index at all.
