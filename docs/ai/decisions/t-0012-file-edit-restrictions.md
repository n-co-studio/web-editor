# Decision 0012 — File Edit Restrictions (Mode Guard)

## Status
Accepted

## Triggers

- type: file
- path: `\.claude/hooks/write-guard\.sh`
- path: `\.claude/repo-mode`
- keywords: `write-guard, mode-guard, REPO_OS_MODE, REPO_OS_UNLOCK_PATH, REPO_OS_SKIP_MODE_GUARD, is_in_repo`

## Context
The template repo ships governance files (hooks, agents, prompts, decisions) that child repos inherit. Without mode-aware restrictions, agents in child repos could accidentally modify template-owned governance, and agents in template mode could accidentally create product code. The mode guard ensures each repo type can only write to structurally appropriate paths.

## Decision
Add a mode-aware file edit restriction system that prevents agents from modifying files outside the active mode's scope:
1. **Three modes**: `template` (governance only — no product code), `child` (product code + limited governance carve-outs), `autonomous` (product code + minimal governance carve-outs). Mode declared in `.claude/repo-mode` (gitignored — not tracked or synced to child repos; Decision 0024). Default when file missing: `child` (most restrictive non-autonomous mode). Template repo operators create this file locally
2. **Default-deny on governance prefixes**: Governance prefixes (`.claude/`, `docs/ai/`, `docs/spec/_templates/`, `.github/`, `AI.md`, `CLAUDE.md`, `repo-os-explainer.html`) are blocked by default. Each mode defines explicit carve-outs (allowlist within governance). New paths under governance prefixes are automatically protected
3. **Carve-out model**: Template mode gets governance access (`.claude/agents/`, `.claude/hooks/`, `.claude/settings.json`, `.claude/settings.local.json`, `.claude/local/sessions/*`, `.claude/local/known-issues.md`, `.claude/local/task-groups/*`, `docs/ai/prompts/`, `docs/ai/decisions/`, `docs/ai/logs/`, `docs/ai/workflow.md`, `docs/ai/quality-gates.md`, `docs/ai/task-groups/_contract-template.yaml`, `docs/spec/_templates/`, `AI.md`, `CLAUDE.md`, `repo-os-explainer.html`, `.github/`) but no product code. Child mode gets product code plus: `docs/ai/decisions/0100+` (project decisions — plain numeric names without `t-` prefix), `docs/ai/logs/`, `docs/ai/governance/`, `docs/ai/task-groups/*.yaml` (non-underscore-prefixed), `docs/spec/compiled/`, `docs/spec/prototypes/`, `.claude/settings.local.json`, `.claude/.automation/reports/` (health reports written by Dev Orchestrator via Bash redirect — runtime artifacts, gitignored; see Decision t-0017 §10), `docs/ai/knowledge-graph/product-graph.yaml` (child-owned product graph; must be writable in child mode to fulfil Decision t-0034 Amendment 3 REQUIRE-attempt close-write obligation). Template decisions (`t-*.md`) are blocked in child mode at write-time (Decision 0022). Autonomous mode gets product code plus: `docs/ai/logs/`, `docs/ai/task-groups/*.yaml` (non-underscore-prefixed)
4. **Immune paths**: `.claude/hooks/write-guard.sh` and `.claude/repo-mode` cannot be modified in any mode — `REPO_OS_UNLOCK_PATH` rejected, no targeted override. Self-protection against circumvention. See point 15 for maintenance procedure
5. **No SessionStart hook**: Mode resolved per-invocation by reading `.claude/repo-mode` directly (~0.1ms file read). Avoids lifecycle hook dependency and race conditions
6. **Decision naming convention** (updated by Decision 0022): Template decisions use the `t-` prefix (`t-NNNN-name.md`) and are blocked in child/autonomous modes at write-time. Child decisions use plain numeric names (`0100+-name.md`, matching `0[1-9][0-9][0-9]-*.md`) and are editable in child mode. The `t-manifest.txt` file lists all template decisions for orphan cleanup in child repos
7. **Analytics passthrough (removed)**: Previously, `.claude/analytics/` paths exited early to prevent mode-guard from interfering with telemetry. Event data now writes to `~/.local/share/repo-os-analytics/<repo-name>/events/`, which is outside the repo tree and outside all governance prefixes. Mode-guard never sees these writes — passthrough removed
8. **State protection (merged)**: `.claude/.state/` write protection and mode enforcement are combined in `write-guard.sh`. State-guard logic runs first (Section 1), then mode-guard logic (Section 2). Previously separate hooks merged for performance
9. **Bash command scanning**: For Bash tool calls without `file_path`, scans command string for write-indicating patterns (redirection `>`, `>>`, `tee`) targeting governance paths. Best-effort heuristic complementing Edit/Write enforcement
10. **Portable path normalization**: Uses `python3 -c "import os.path,sys; print(os.path.normpath(sys.argv[1]))"` with raw-path fallback. No `realpath -m` (not available on macOS)
11. **Three-tier override mechanism**: `REPO_OS_UNLOCK_PATH=<exact-path>` (single governance file unlock, immune paths rejected), `REPO_OS_MODE=<mode>` (force mode — emergency template-level access in child repos), `REPO_OS_SKIP_MODE_GUARD=1` (disable entirely — recovery/debugging). All overrides logged via `log_override()`. Persistent audit: mode-guard override entries in `overrides.log` are surfaced via `Overrides:` git trailer advisory in `pre-commit-gates.sh`
12. **Hook ordering**: mode-guard runs after state-guard (`.state/` already protected) and before branch-guard (mode is more fundamental than plan approval — surface the structural block first). Order in `settings.json`: state-guard → mode-guard → write-guard Section 3 (Edit/Write) or branch-guard (Bash) → pre-commit-gates → pre-push-gates. **Ordering within each matcher group in `settings.json` is significant** — hooks execute in array order, so the sequence determines which check surfaces first on failure. Reordering hooks within a matcher group changes the user-visible error. This ordering is a deliberate architectural choice, not incidental
13. **LOCK semantics**: Blocks Edit, Write, and Bash writes only. Read tool always allowed in all modes
14. **Underscore-prefix convention**: In `docs/ai/task-groups/`, underscore-prefixed files (e.g., `_contract-template.yaml`) are template-owned governance. Non-underscore YAML files are project contracts. Child/autonomous modes can write non-underscore files only; template mode can write `_contract-template.yaml`
15. **Immune path maintenance**: To perform legitimate maintenance on immune paths (`write-guard.sh`, `repo-mode`): (a) set `REPO_OS_SKIP_MODE_GUARD=1` — this disables the entire guard for the session and is logged in `overrides.log`; (b) as a last resort, Python file I/O (`python3 -c "open(...).write(...)"`) bypasses Bash command scanning (which only detects `>`, `>>`, `tee`). Prefer (a) — it provides an audit trail
16. **Fast-exit for non-template modes**: After resolving mode, child and autonomous modes skip full governance path classification — exit 0 immediately after an immune path check. Rationale: product code always passes in non-template modes; governance path blocking is deferred to review-time (PR review, code review). The immune path check (`write-guard.sh`, `repo-mode`) is retained across all modes for self-protection. Template mode retains full edit-time governance enforcement because editing product code is structurally wrong in that mode. This eliminates mode-guard classification overhead for ~90% of repos (child/autonomous) while preserving template protection. Supersedes: previously, mode-guard ran full path classification in all modes on every Edit/Write/Bash
17. **Out-of-repo boundary**: Paths outside the repository root are out-of-scope for all governance hooks. Shared boundary utilities in `_analytics-helper.sh` implement this: `normalize_path()` (portable `normpath` via Python, raw-path fallback — supersedes the inline normpath from point 10), `resolve_path()` (absolute path resolution via `os.path.abspath`), and `is_in_repo()` (prefix-checks resolved path against repo root). Mode-guard calls `resolve_path()` + `is_in_repo()` before path classification — out-of-repo paths exit 0 (silently allowed) because they cannot affect repo governance. State-guard calls `resolve_path()` + `is_in_repo()` to confirm paths are in-repo before matching against `.claude/.state/` — preventing false positives on out-of-repo paths that happen to contain `.claude/.state/` substrings. This prevents misclassification of external tool paths (e.g., `~/.claude/plans/`) as "product paths" in template mode

## Consequences
- `.claude/hooks/write-guard.sh` is the unified enforcement point — state protection (Section 1) and mode enforcement (Section 2) in a single hook
- `.claude/repo-mode` declares the repo's operating mode; changing it changes the entire governance posture
- Template decisions (`t-*.md`) are blocked in child/autonomous modes at write-time, establishing a clear boundary between template governance and project-specific decisions (0100+). See Decision 0022 for the `t-` prefix naming convention
