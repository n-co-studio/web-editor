# Decision Digest — Foundational Decisions

Last synced: 2026-03-22

> Full decision files are authoritative. This digest is a compressed reference for context-efficient loading.

**Decision 0001 — Repo OS Baseline.** Establishes the foundational operating model: explicit operator-vs-agent authority boundary, prompt system (Prompt 0 spec → Prompt A init → Prompt B build, extended by Decisions 0006/0010), mandatory verification gates before commits, session-based work with high-signal logging, and GitHub template repo as source of truth. `AI.md` is the canonical governance index. Commit 0 (Prompt A output) must exist before any product code. All subsequent decisions extend this baseline. Triggers on `AI.md`, `docs/ai/prompts/prompt-.*\.md`, keywords: prompt system, verification gate, session-based.

**Decision 0002 — Decisions Are Mandatory (Commit-Blocking).** Accepted decisions in `docs/ai/decisions/` are mandatory — not advisory. For any change, applicable decisions must be identified and followed; conflicts require proposing a new decision record before proceeding. Decision violations block commits (and therefore pushes). Gate A1 enforces compliance mechanically via the trigger parser (Decision 0004). The `Decisions:` git trailer on commits creates a permanent compliance record. Triggers on `docs/ai/decisions/.*\.md`, keywords: mandatory, commit-blocking.

**Decision 0003 — Agent Structure Standardization.** All agents in `.claude/agents/` must follow a standard structure: mandatory shared files (`_agent-glossary.md`, `_agent-workflow.md`), YAML frontmatter for invocable agents (orchestrator exempt per 0004), and defined role/scope/constraints/output/invocation sections. Terminology aligns with glossary; gate definitions align with `quality-gates.md`. Decision 0004 extends this by requiring `tools`/`disallowedTools` frontmatter for runtime-enforced tool boundaries. Triggers on `\.claude/agents/.*\.md`, keywords: frontmatter, disallowedTools, tools:, model:.

**Decision 0004 — Mechanical Enforcement Layer.** The enforcement backbone making governance violations structurally impossible rather than merely discouraged. Implements: subagent YAML frontmatter with `tools`/`disallowedTools` for runtime tool boundaries, frontmatter hooks (`agent-git-guard.sh`) blocking subagent `git commit`/`git push`, orchestrator exception (no frontmatter — only agent permitted to commit), team settings (`.claude/settings.json`), and the full hook chain (`write-guard.sh`, `bash-guard.sh`, `pre-commit-gates.sh`, `pre-push-gates.sh`, `plan-approval.sh`, `session-close-check.sh`, `state-writer.sh`, `hvst-failure-tracker.sh`). State directory (`.claude/.state/`) provides session-scoped governance evidence. Sentinel protocol (`GATE_RESULT:`) creates machine-readable contract between agents and hooks. All decisions 0005+ extend this hook infrastructure. Triggers on `\.claude/hooks/.*\.sh`, `\.claude/settings\.json`, keywords: PreToolUse, PostToolUse, SubagentStop, Stop, phase-state, _phase-helper.

**Decision 0025 — Pragmatist Agent.** Dual-mode over-engineering review agent. Brief-Advisory mode (Prompt T) dispatched as 4th core specialist alongside Architect, Exploration, and Critic — standard advisory format, no GATE_RESULT. Plan-Gating mode (Prompt B) reviews implementation plans before build — uses GATE_RESULT sentinel with FUNDAMENTAL-MISMATCH (blocking) and OVER-ENGINEERED (approved) severities. Auto mode degrades BLOCKED to advisory-with-warning to prevent unresolvable sessions. State file: `pragmatist-signed`. Triggers on `\.claude/agents/pragmatist\.md`, keywords: pragmatist, over-engineer, yagni, plan-review.

**Decision 0026 — Session-Type Validation for Task Group Briefs.** Mechanical check detecting when a brief contains `### Task Group` but the session was initialized with a non-taskgroup session type. Orchestrator writes `.claude/.state/brief-has-taskgroup` fingerprint; `check_taskgroup_brief_mismatch()` in `_phase-helper.sh` blocks at Gate 2b in both `bash-guard.sh` and `write-guard.sh` before any implementation proceeds. Override: `REPO_OS_SKIP_TASKGROUP_CHECK=1`. Triggers on `\.claude/hooks/(bash-guard|write-guard|_phase-helper)\.sh`, keywords: taskgroup_brief_mismatch, brief-has-taskgroup.

**Decision 0027 — Agent Tool Governance Gate.** Closes the Agent tool bypass that allowed write-capable subagents in no-write sessions (Prompt T, A, C, D, ephemeral). `pretooluse-permission.sh` gates Agent tool calls: fail-closed on missing phase-state, allowlist-based check for no-write session types. Read-only agent allowlist (`_PERMISSION_READONLY_AGENTS`) in `_permission-allowlist.sh`. Bash deny pattern blocks `claude` subprocess escalation (exempt when `CLAUDE_HEADLESS=1`). Override: `REPO_OS_ALLOW_AGENT=1`. Triggers on `\.claude/(hooks/(pretooluse-permission|_permission-allowlist)|settings\.json)`, keywords: is_readonly_agent, agent_gate.

**Decision 0028 — Worktree State Isolation.** Hardens governance state boundary for worktree-isolated subagents. `state-writer.sh` refuses to write governance state files when `is_worktree()` detects a worktree CWD — verdicts silently skipped with `worktree_blocked` audit log. State reads pass through (worktree subagents operate under parent session's governance). If governance evidence is needed, re-dispatch agent without worktree isolation. No override — unconditional guard. Triggers on `\.claude/hooks/(state-writer|_analytics-helper)\.sh`, keywords: is_worktree, worktree_blocked.

**Decision 0029 — Operator Acknowledgment Enforcement.** Generalizes operator-acknowledgment by renaming `taskdef-brief`'s `op-review` phase to `approval`, activating the existing `has_plan_gate`/`advance_phase` substance check that requires `plan-approved` state file. `plan-approval.sh` Gate 1 broadened from `\bplan\b` to `\b(plan|brief|task)\b`. New `has_operator_gate` helper in `_phase-helper.sh` (structural scaffolding, no current consumers). Any future session type needing operator approval can use the `approval` phase name for automatic enforcement. Triggers on `\.claude/hooks/(_phase-helper|plan-approval)\.sh`, keywords: approval, has_operator_gate, taskdef-brief.
