# Session Type: Automation

Decision 0017. Optional headless runner infrastructure in `.claude/.automation/`. Disabled by default in `config.yaml` (`runner.enabled: false`); the live toggle is `config.local.yaml`, which the runner bootstraps with `enabled: true` on first start. When enabled, runners process queued task briefs via `claude -p` with full governance parity.

**Runner lifecycle:**

1. **Dequeue** — pick oldest `approved` queue entry, acquire flock-based queue lock, transition to `running`, release lock
2. **Pre-launch** — create branch (or check out existing for task groups), register session, write `plan-approved` state file, pre-seed `.claude/.session-id`. Phase-state is agent-initiated: the agent calls `init_phase()` as its first Bash action (fast-exits bash-guard.sh — no redirect/tee). With fail-closed enforcement (Decision 0019), edits before `init_phase()` are blocked when the sentinel is present. Custom runners MUST ensure `init_phase()` is called before any Edit/Write tool use
3. **Launch** — invoke `claude -p` with `--disallowedTools` permission profile and assembled prompt (template-based or inline fallback). Decision cache entries (max 10) are prepended to the prompt. The brief text contains the task contract inline as a `### Task Contract` section (Decision 0020); the runner includes the full brief in the assembled prompt and the agent extracts and writes the contract during init
4. **Post-session** — detect outcome (completed/failed/review), perform external cleanup (solo merge, session registry, branch sealing — Stop hook does not fire in headless mode), transition queue entry

**Toggle semantics:**

| Method | Effect |
|--------|--------|
| `config.local.yaml` → `runner.enabled: false` (or use Prompt D) | Daemon sleeps 30s between checks. Queued entries preserved. This is the authoritative live-toggle file: `_parse_config_field` reads it first and any non-empty value wins. Prompt D writes this file and reports the effective value with its source. |
| `config.local.yaml` → `runner.enabled: true` (or use Prompt D) | Daemon processes queue normally. Prompt D writes this file and clears any HALT/FORCE-HALT flags. |
| `config.yaml` → `runner.enabled: false` | Shipped default for a fresh install or child repo. Effective only when `config.local.yaml` does not set the field (i.e., before first daemon start). Do not use as the live toggle — `config.local.yaml` wins the precedence contest and this file is git-tracked. |
| Create `.claude/.automation/HALT` file (`queue-cli.sh halt`) | Graceful stop. **Once the flag exists, no new entry starts**: it is checked at the top of the loop and again after dequeue, immediately before launch; an entry caught in between is returned to `approved/` unstarted with its retry and deferral counts untouched. A session already running finishes first — this cannot interrupt the brief in flight. Residual window: the re-check runs in the daemon loop, before `_run_single_entry` creates the branch/worktree and registers the session. A flag raised in that short setup span (a few seconds, before `claude` is exec'd) is not seen by the re-check — a plain HALT lets that one session run to completion, FORCE-HALT kills it on the watcher's first poll. The dirty-tree cleanup (`git checkout -- .` / `git clean -fd`) also runs before the re-check |
| Create `.claude/.automation/FORCE-HALT` file (`queue-cli.sh force-halt`) | Immediate stop. Watched DURING the session: a per-entry watcher polls every 5s and signals the `claude` child (SIGTERM, then SIGKILL after 10s), then the daemon loop sweeps the worktree and exits. The kill is not counted against the circuit breaker. An entry dequeued but not yet launched when the flag appears is returned to `approved/` rather than launched and killed |
| Remove both files (`queue-cli.sh resume`) | Daemon resumes on next start. Clearing BOTH matters — a leftover `FORCE-HALT` ends the next start at the top of the loop |

**Escalation:** When a headless session exits at an `operator`-tagged phase, the runner writes an escalation file (`.claude/.automation/escalations/`) and transitions the queue entry to `review` status. Eleven escalation types: `gate-failure`, `governance-block`, `phase-tag-escalation`, `ambiguity`, `scope-exceeded`, `dependency-missing`, `security-risk`, `structural-change`, `scope-deviation`, `stale-branch`, `parent-discarded`. The `scope-deviation` type includes `scope_classification` (briefed/unbriefed-in-scope/out-of-scope) and `risk_gain` context for operator review.

**Queue validation:** Before dequeue, entries are validated: required fields (id, session_type, status), session type against Decision 0014 enum (`get_phases_for_type` must return non-empty), brief content non-empty and max 50KB, branch name sanitized to `[a-zA-Z0-9/_-]` max 100 chars. External-source entries may require HMAC-SHA256 signature verification (opt-in via `hmac_secret` in runner config).

**Decision cache:** Two-level merge — project-level (`.claude/.automation/decision-cache.yaml`) and local-level (`.claude/.automation/local-decision-cache.yaml`). Local can extend or narrow enforcement, never elevate (cannot change REQUIRE to GUIDE). Merged output: max 10 entries, each formatted as `Decision NNNN: summary (MECHANISM)`, prepended to the assembled prompt.

**File locking:** `flock`-based exclusive lock on `.claude/.automation/.queue-lock`. 5-second timeout, fails with error. Lock scope: single queue state transition (not entire session). Callers wrap individual `_transition()` calls.

**Dev orchestrator:** Cross-brief health reports between task group briefs. Runner invokes after content brief completes and before merge brief starts. Uses the `audit` session type. Reports go to `.claude/.automation/reports/` (gitignored). See `.claude/agents/dev-orchestrator.md`.

**Auto mode activation:** When the operator selects auto mode during plan approval for a task group session, the `plan-approval.sh` hook automatically queues remaining pending briefs from the task group contract, enables the runner (`config.yaml` → `runner.enabled: true` via `_automation-bridge.sh`; note: `config.local.yaml` takes precedence if present — if the daemon is disabled in `config.local.yaml`, use Prompt D to re-enable), and starts the daemon. Daemon output is logged to `.claude/.automation/logs/runner.log` (gitignored). Briefs are queued with `auto_mode: true` and `solo_mode: true` (final brief only). The current session continues interactively; subsequent briefs execute headlessly via the runner. Idempotent: briefs already in the queue (pending-review, approved, or running) are skipped. Brief content convention: `.claude/.automation/briefs/{group-name}/brief-{N}.md` — if pre-populated by the operator, the prompt assembler reads them; otherwise sessions receive governance context and contract metadata via the taskgroup-brief template. Activation requires the automation layer to be installed (config.yaml must exist). Standalone (non-task-group) auto mode sessions are unaffected.

**Circuit breaker:** 3 consecutive global failures pause the daemon (60s sleep between checks), and the count persists in `.claude/.automation/queue/.circuit-breaker` — restarting the daemon does not clear it. Three exits, in the order an operator should reach for them:

- `queue-cli.sh reset-breaker` — the sanctioned reset. A successful session also clears the counter, but the breaker prevents any session from starting, so waiting for one is not a recovery path.
- **Self-expiry.** Once `runner.circuit_breaker_cooldown_seconds` (default 1800) has passed since the last failure, the breaker reports open so ONE probe entry can run. The failure count is deliberately NOT cleared, so a failed probe re-trips for another full window — one attempt per window, not a retry loop. Set the field to `0` to disable expiry entirely.
- Fixing the cause, then either of the above.

The breaker **fails closed** on state it cannot read: a `.circuit-breaker` whose `consecutive_failures` or `last_failure_epoch` is missing or non-numeric stays tripped rather than expiring on a value it cannot trust. A file written before 2026-10-20 has no epoch field and therefore never self-expires — use `reset-breaker`. A file with no count line at all does not trip. While tripped the runner writes health status `circuit-breaker`, not `idle`. Recovery walkthrough: `.claude/.automation/docs/blocker-playbook.md` §8.

**Work-order deferral:** When the runner dequeues an entry that belongs to an escalated or failed work order, the entry is moved back to `approved/` without incrementing its retry count. This prevents sequential briefs from executing while a dependency is unresolved or a prerequisite has failed. Escalated work orders have a sibling in `review`/`blocked` status; failed work orders have a sibling in `failed` status (the `failure_entry_id` field identifies which entry caused the failure). When the operator resolves the blocking sibling and reopens the work order (`wo_reopen` / `queue-cli.sh reopen-wo`), the deferred entries resume automatically on the next poll cycle — they are already in `approved/` and eligible for dequeue. The deferral is logged as an `entry-deferred` event in the review log.

**Intake CLI:** Standalone entry point for queue entry creation without the interactive bridge (`plan-approval.sh`). Usage: `.claude/.automation/lib/intake.sh --brief <path> [--auto-approve] [--session-type <type>] [--solo] [--push]`. Auto-enables the runner (`config.local.yaml` → `runner.enabled: true`) when entries are added. Accepts brief path, session type (Decision 0014 enum), auto-approve (place directly in `approved/`), solo mode, and push-on-complete flags.

**push_on_complete:** Per-entry opt-in flag for branch push after session completion. When `push_on_complete: true` in the queue entry: solo sessions push main after merge, non-solo sessions push the feature branch. Push is advisory — failure warns but does not block. Enabled via `--push` flag in intake CLI or `push_on_complete` field in queue entry YAML.

**Scope classification:** The pre-commit gate (`pre-commit-gates.sh`) classifies staged files against the task contract's `scope_files` list at commit time. Three categories: **briefed** (exact match — no action), **unbriefed-in-scope** (parent directory matches a scope file's parent — advisory escalation with risk/gain context), **out-of-scope** (no match — blocking, commit denied). The agent populates risk/gain context via `.claude/.state/scope-risk-gain` state file before commit. Escalation files are written to `.claude/.automation/escalations/` for runner integration. Classification is path-based (deterministic, no LLM). See Decision 0017 § Scope Classification Model.

**PermissionRequest hook:** The `permission-request.sh` hook (wired to the `PermissionRequest` event in `settings.json`) auto-approves curated tools and Bash commands, denies dangerous patterns, and falls through to the VS Code dialog for unknown commands. Every request is logged to `.claude/.automation/logs/permission-audit.log` (gitignored, append-only). Deny list has priority over allow list (fail-safe). Does not fire in `claude -p` mode — headless sessions use `--disallowedTools` profiles instead. See Decision 0017 § PermissionRequest Hook.

**AskUserQuestion deny hook:** The `ask-user-deny.sh` PreToolUse hook blocks `AskUserQuestion` in headless automation mode when `CLAUDE_HEADLESS=1` is set (by `runner.sh`). Defense-in-depth alongside `--disallowedTools`. Interactive sessions pass through unaffected. Blocked sessions are instructed to write escalation files instead.
