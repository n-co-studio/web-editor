# Session Types: eval and eval-cell

Evaluation study sessions orchestrate multi-arm A/B studies over the existing headless
runner without governance state collisions. Two session types:

- **`eval`** — the conductor session. Runs `prompt-eval-study.md`; full governance applies
  to its own committed study records. Never merges cell branches to main.
- **`eval-cell`** — per-cell agent run. Each cell runs in its own worktree with a
  per-cell `REPO_OS_SESSION_ID` and a per-process sidecar. Cells do NOT merge to main
  and do NOT seal the shared branch.

Decision t-0046 Amendment 1.

## Session Type: `eval` (Conductor)

### Detection

Detected at session init when:
- Brief or session context references `prompt-eval-study.md`, OR
- Current branch starts with `eval/*` (study branch pattern), OR
- Operator explicitly sets session type to `eval`

### Phase Sequence

```
init → design → pre-register → launch → await → collect → judge → report → close
```

| Phase | Tag | Description |
|-------|-----|-------------|
| `init` | agent | Read AI.md, eval nomenclature, conductor lib; confirm study manifest |
| `design` | agent | Intake study design from `_eval-study-brief.md` or operator prompt; finalize arms/tasks/n_reps/rubric. No file writes — design is finalized in memory before pre-register. |
| `pre-register` | agent | Fill + commit `study.yaml` (BEFORE any cells run); generate + commit `shuffle-manifest.json` |
| `launch` | agent | Call `eval_launch_cells` → expand arms×tasks×reps → queue entries + cell stubs |
| `await` | agent | Call `eval_await_cells` → poll until all cells terminal; handle partial failures |
| `collect` | agent | Call `eval_collect_artifacts` → populate cell records from completion reports |
| `judge` | agent | Call `eval_extract_submission` per cell + `eval_trigger_judge` → enqueue judge entries |
| `report` | agent | Call `eval_generate_report` → commit `report.md` + `cell-index.yaml`; apply decision rule |
| `close` | agent | Prune cell branches; update study status to `completed`; write session log |

**Write-allowed phases:** `pre-register`, `launch`, `collect`, `judge`, `report`, `close`

**Gate profile:** Full governance (A1–A6, B1–B3) for the conductor's own commits
(study records). Cell branches are NOT merged to main — they are evaluation artifacts.

### Committed Records

The conductor writes committed study records to `docs/ai/eval/{study_id}/`:
- `study.yaml` — pre-registered manifest (MUST be committed before cells run)
- `shuffle-manifest.json` — seeded arm-order blinding evidence
- `cells/{arm_id}-{task_id}-r{rep}.yaml` — per-cell records (metrics + pointers, no raw)
- `cell-index.yaml` — denormalized projection for report generation
- `report.md` — filled `_eval-report.md` template with verdict

### Close Protocol

1. Mark study status `completed` in `study.yaml`; commit study records
2. Prune cell branches: `git branch -d eval/{study_id}/**` (pruned, NOT merged to main)
3. Write session log at `docs/ai/logs/sessions/session-{id}.md`
4. Commit session log
5. Non-final brief: leave feature branch open (no merge to main)

## Session Type: `eval-cell` (Per-Cell Agent Run)

### Detection

Detected when:
- Session type is explicitly `eval-cell` (set by `intake.sh --session-type eval-cell`), OR
- Branch matches `eval/{study_id}/{arm_id}/{task_id}/r{rep}` pattern

### Isolation Envelope

**State-collision prevention** (resolves the governance self-interference risk):

| Property | Mechanism |
|----------|-----------|
| Per-cell session identity | Each cell gets its own `REPO_OS_SESSION_ID` (generated by conductor at launch) + per-process sidecar `.session-id.<PPID>` |
| Per-cell worktree | Runner creates `{repo}/.worktrees/{cell_session_id}/` — cell writes never touch other cells' state |
| No close-merge | `eval-cell` close protocol SKIPS merge to main — cell commits stay on cell branch |
| Daemon registry isolation | Daemon/session-registry sees each cell as a distinct registered session (distinct session ID + distinct worktree) |
| Branch pruning at study close | Cell branches `eval/**` are pruned (not merged) by the conductor at study close |

### Phase Sequence

```
init → build → commit → close
```

| Phase | Tag | Description |
|-------|-----|-------------|
| `init` | agent | Checkout cell branch; initialize phase state with per-cell session ID |
| `build` | agent | Execute the task against the target repo (or this repo for template-level studies) |
| `commit` | agent | Commit task outputs to cell branch; write `diff.patch`, `timing.json`, `tokens.json`, `transcript.log` to gitignored raw dir |
| `close` | agent | Write completion report to `raw_artifact_dir/completion-report.yaml`; DO NOT merge to main; DO NOT seal branch; signal completion to conductor |

**Write-allowed phases:** `build`, `commit`, `close`

### Gate Profile

Two modes depending on the arm being tested:

| Arm type | Gate profile |
|----------|-------------|
| **Standard arm** (measuring task quality, not governance) | A4 safety only — no process/quality/review gates. Full-governance ceremony would contaminate the measurement |
| **Full-governance arm** (measuring whether governance context improves accuracy) | Full gate/hook stack runs against the TARGET repo. The arm condition IS governance context |

The arm's gate mode is declared in `study.yaml` under `arms[].gate_profile` (values: `a4-only`, `full`). The conductor sets `REPO_OS_CELL_GATE_PROFILE` in the cell's env before launching.

### Cell Branch Lifecycle

```
Cell branch: eval/{study_id}/{arm_id}/{task_id}/r{rep}
  Created at: eval_launch_cells (from study's target_baseline_sha)
  Commits: cell's build + close outputs
  Pruned at: close phase — conductor calls git branch -d eval/{study_id}/**
  Never merged to main
```

### Avoiding Governance Self-Interference

The isolation envelope prevents state collisions because:
1. **No shared `.session-id`**: per-PPID sidecar + per-cell worktree → distinct session IDs
2. **No concurrent merges to main**: cells commit to cell branches only
3. **Distinct phase-state paths**: each worktree has `wt-sessions/{cell_session_id}/phase-state` — no overlap with the conductor's or other cells' state
4. **Registry visibility**: the session registry sees each cell as live for its run, then removes it at close — no orphaned entries block the conductor

## Mode Parity

Both `eval` and `eval-cell` work in template mode and child (project) mode:

| Context | Target repo | Committed records root | Raw artifacts root |
|---------|------------|----------------------|-------------------|
| `run_context: template` | This repo (governance machinery) | `docs/ai/eval/{study_id}/` in this repo | `.claude/.automation/reports/eval/{study_id}/` in this repo |
| `run_context: project` | Child repo path (from `target_repo` in study.yaml or `EVAL_TARGET_REPO` env var) | `docs/ai/eval/{study_id}/` in the CONDUCTOR's repo | `.claude/.automation/reports/eval/{study_id}/` in the conductor's repo |

Child repos write to `docs/ai/eval/` via the `is_carved_out` carve-out added in Decision t-0046
(`_mode-guard-helper.sh`). No additional unlock flags needed.

**To run a project-level study in a child repo:**
1. Create `docs/ai/eval/{study_id}/study.yaml` with `run_context: project` and `target_repo: /path/to/child/repo`
2. Commit the study manifest (pre-registration)
3. Run `prompt-eval-study.md` — the conductor resolves target from the manifest
4. Cell agents are launched against the target repo (cells run in child repo worktrees)
5. Results and reports are committed to the CONDUCTOR's `docs/ai/eval/{study_id}/`

## Judge Session

Judge sessions run under the `judge` permission profile (read-only). They are dispatched
as `eval-cell` queue entries with `permission_profile: judge` set in the queue entry YAML.
`eval_trigger_judge` calls `queue_enqueue` with `permission_profile=judge` (arg 9);
the runner reads this field and passes it to `_run_single_entry` → `get_disallowed_tools "judge"`.
Existing queue entries without this field default to `build` (backward-compatible).

**Judge profile** (see `permission-profiles.sh`):
- Blocks: Edit, Write, Bash(git commit:*), Bash(git push:*), AskUserQuestion
- Permits: Read, Grep, Glob, Bash(read-only commands)

**Data flow:**
1. Conductor generates `shuffle-manifest.json` (seeded, committed)
2. Conductor writes judge brief to `raw_root/judge-briefs/judge-{study_id}.md`
3. Judge reads shuffle_manifest + rubric + `submission/submission.patch` per cell
4. Judge writes raw scores to `raw_root/{cell_id}/judge-scores.json` (gitignored)
5. `eval_generate_report` joins judge scores with cell records via shuffle_manifest

**Judge isolation:** One judge entry per study. If judge fails, `judge_status` is marked
`pending` in the report (not a silent omission). A missing judge does not block report
generation.
