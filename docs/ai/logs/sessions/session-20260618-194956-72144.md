## Summary

Operator feedback: the step-5 prompt ("Apply my pending NCO Studio edits.") was too ambiguous for an agent with
no repo-OS context — nothing tells it there's an MCP connection, a queue, or diffs. The tool itself is built for
repo OS but is agnostic, so the on-page prompt must stand on its own.

Finding (verified in `packages/mcp-server/src/server.ts`): the MCP tool descriptions are already self-documenting
— `get_pending_visual_changes` explains how to apply each diff (source-aware, @media/@layer preserving, reorder,
insert, remove). So the only gap was that the prompt never named the server or the tools. Once it does, any
MCP agent reads the descriptions and acts.

## Change (both pages, copy-only)

Replaced the prompt in the "Run the loop" step (SetupGuide.tsx + MotionSetup.tsx) with an explicit, combined
plain-language + tool-naming instruction:

> Check my nco-web-editor MCP server for pending visual edits from the browser. Apply each diff to the source
> file it points to, then mark it done — using the get_pending_visual_changes and acknowledge_visual_change tools.

Plus a note that `nco-web-editor` is the `mcpServers` key from the connect step and should be swapped for
whatever the operator named it (it can differ per environment/instance).

## Forward idea (not implemented — product, needs its own brief)

The most durable way to make this "effective outside repo OS" is for the MCP server to expose an **MCP prompt**
(MCP supports server-provided prompts, not just tools) — e.g. an "Apply NCO Studio visual changes" prompt the
host surfaces directly, so the operator doesn't have to craft any text. Worth considering as a product
enhancement to `packages/mcp-server`.
