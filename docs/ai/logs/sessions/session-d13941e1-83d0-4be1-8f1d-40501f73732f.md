## Summary

27 build-commit cycles rebuilt `examples/demo-app` from an earlier multi-page
guide into a single page: hero → three-step how-it-works row → tabbed guide
(Set it up / How to use / Troubleshooting), rendered over an animated green
lava canvas field. A `src/motion/` subtree (a second "kinetic blueprint"
route) and the header, footer, FAQ, hero CTA, and card chrome were removed
along the way. Design tokens in `src/tokens.css` grew to carry the new scale.

Two findings from the session are worth more than the visual diff itself:

**The MCP bridge was never connected.** `nco-web-editor` was declared under
`mcpServers` in `.claude/settings.json`, which Claude Code does not read —
project-scoped MCP servers are configured in `.mcp.json` at the repo root.
`claude mcp list` never listed the server, so no cycle of this session had
access to `get_pending_visual_changes` / `acknowledge_visual_change`. Every
cycle was driven by reading `.nco-web-editor/pending-queue.json` directly and
acknowledging by removing it (safe: the server lock held a dead PID). Fixed in
cycle 27; the server binary itself is healthy — a stdio probe completes the
handshake, clears the stale lock, and binds port 7890. **The fix does not take
effect until the session restarts**, since Claude Code connects MCP servers at
startup.

**The demo app was documenting the same misconfiguration as advice.**
`Troubleshooting.tsx` recommended `.claude/settings.json` as "the simpler of
the two" for Claude Code, and `SetupGuide.tsx` listed it as the Claude Code
config path. A user following the guide would land in exactly the silent
failure this repo spent 27 cycles in. Corrected at close.
