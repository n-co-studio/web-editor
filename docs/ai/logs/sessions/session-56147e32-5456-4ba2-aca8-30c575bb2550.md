## Brief
Reorder List Panel — a toolbar-anchored panel that activates with the Reorder tool,
lists the selected container's direct element children by name, and lets the operator
drag list rows to reorder them, committing each move through the existing reorder
change pipeline (captured, batched, undoable). Complements — does not replace — the
existing in-place drag reorder.

## Summary
Added a toolbar-anchored `ReorderPanel` for the chrome-extension content script.

- **`reorder.ts` — commit seam.** New `commitFromIndex(fromIndex, toIndex)` mirrors
  the `onPointerUp` commit path: it delegates the DOM move to the shared private
  `commitReorder` (so the `moveBefore`/`insertBefore` feature-detect stays in one
  place) then fires `onCommitCb` with the frozen child-order snapshot — the move
  flows through the exact same `ReorderChange` pipeline as an in-place drag. One call
  = one `ReorderChange`. A no-op guard skips `toIndex === fromIndex` and
  `fromIndex + 1` so an in-place drop enqueues nothing. `commitReorder` gained an
  optional `el` param (defaults to `currentElement`) so the panel can move any row's
  element, not just the selected one. Added a `readonly childSnapshot` getter over
  `originalChildOrder` (element-only) so callers build a `SiblingAnchor[]` whose
  indices align 1:1 with `commitFromIndex`.
- **`reorder-panel.ts` — new `ReorderPanel`.** Flat vertical list, one row per element
  child. Labels source from `buildSiblingAnchor` with a mandatory fallback
  (`buildSiblingAnchor` only sets `label` for asset-backed elements):
  `label → aria-label → truncated textContent → #position`. Asset-backed rows get a
  16px thumbnail (`onerror` → label-only); generic rows get a muted mono `<tag>` chip
  so duplicate/empty labels stay distinct. Pointer-capture 1D drag (repo convention —
  not HTML5 DnD) with a drop indicator between rows; drop emits exactly one
  `(from, to)` via the commit callback. Shift+ArrowUp/Down keyboard reorder through
  the same path; ARIA `role=list/listitem` + `aria-posinset/setsize` + a persistent
  polite live region announcing new positions. Blocked/empty state for < 2 element
  children or a non-reorderable container. Anchored to the LEFT of the toolbar
  (`getButtonPosition('reorder')`, `+ TOOLBAR_WIDTH + 8`) — never right-docked
  (feature-004 owns the right edge). Header-drag repositioning; symmetric drag-listener
  teardown; selection highlight by element identity.
- **`index.ts` — lifecycle.** `renderReorderPanel(el)` helper builds anchors from
  `reorderEditor.childSnapshot` (guarantees index alignment) and renders + highlights
  the panel. Wired into the `reorder` branch of `activateToolForElement`, the
  `makeReorderCommit` re-render lambda (both surfaces refresh on every commit), and
  `refreshReorderAfterHistoryChange` (EditHistory rebuilds the DOM without the lambda,
  so undo/redo refresh the panel explicitly). Teardown added to every cleanup sweep,
  `deactivate()` (cleanup + null), and the toolbar-drag `onMove` reposition.
