## Summary

Implemented all deliverables for NCO Studio Launch Brief 6 (Finalize Package Builds & Dependency Hygiene). This brief corrects the pre-existing tsup DTS build failure in `packages/dev-plugin` identified in Brief 5.

### packages/dev-plugin/tsconfig.json

- Removed `composite: true` from `compilerOptions`
- Root cause: tsup's DTS generation creates an in-memory TypeScript project that only lists entry files; `composite: true` enforces that ALL input files be listed in the project (TS6307), which tsup's virtual project does not satisfy for transitively-imported files (`src/vite.ts`, `src/types.ts`)
- `composite: true` is needed only for `tsc --build` project references; dev-plugin uses tsup (not `tsc --build`), so it provides no benefit

### tsconfig.json (root)

- Removed `packages/dev-plugin` from the `references` array
- TypeScript project references require `composite: true` in the referenced project; retaining the reference after removing `composite` would have caused `tsc --build` at root to fail with TS6306
- `packages/shared` retains `composite: true` (uses `tsc --build`) and stays in references

### package-lock.json

- Updated by `npm install` to add `examples/demo-app` workspace resolution and tsup/esbuild platform-specific binaries (introduced by Brief 4 demo app + workspace tsup dependency installation)
