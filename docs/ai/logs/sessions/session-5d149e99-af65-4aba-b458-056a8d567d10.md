# Session — 0.3.0 prep: template sync, a11y/token audit, landing page, store assets

- **Session ID:** 5d149e99-af65-4aba-b458-056a8d567d10
- **Type:** standard
- **Branch:** fix/post-launch-links
- **Date:** 2026-10-26

## Why

Three strands converged on one branch ahead of 0.3.0. The repo-OS template had
moved on and the local tree held a stale sync that had to come out before the
real one could land. The landing page was rebuilt against an updated Figma
design and repositioned to lead on MCP. And an accessibility and token audit
had produced a large set of changes that needed reviewing rather than trusting.

## What changed

**Template sync (Part A).** The stale `c555fc3` sync was discarded first: 39
modified files restored, 6 additions unstaged and deleted, leaving `.claude/`
and `docs/ai/governance/` clean and the 80 product files untouched. Then
`origin/main` was merged — a fast-forward to `29c2ff2`, taken only after
confirming zero overlap between the 165 files main touched and the 80 in
flight. `remote.template.tagOpt=--no-tags` was set after a `git fetch template`
pulled 125 template tags into the local repo; they were deleted.

**Landing page.** Rebuilt against Figma 52:3788 across several design
revisions. A shared `Stepper` component replaced repeated step markup; the
hero palette was retuned to the logo's spectrum; tab states were taken from
the Figma component set (52:3865) rather than guessed; bold weights were
unified through `--fw-strong`. Copy throughout now leads on MCP, which is the
actual differentiator — competing visual editors generate a prompt to paste,
while this dispatches a batch to the user's own MCP server.

**Store assets.** The five white-ground screenshots were replaced by four
dark-ground ones, with the promo tile and store icon re-cut to match. The
store listing's short description was rewritten to lead on MCP and is
byte-identical in `docs/store-listing.md` and `manifest.json`.

**Theming misses found in review.** Six raw colour literals in
`content/editing/insert-panel.ts` and one each in `content/tokens/snapping.ts`
and `content/selection/panes/console-pane.ts` were panel chrome that the audit
had missed. They are not the same class as the deliberately unthemed on-page
indicators (`SELECTION.ring`, `HANDLE_COLORS`, `DROP_INDICATOR`), which are
mode-coded and must stay fixed because they are drawn over pages of unknown
colour. The giveaway in each case was a sibling property on the same element
already being themed. Two were real defects rather than cosmetic:

- `insert-panel.ts` used `#10b981` as a tab underline and selected-item border.
  It measures 2.54:1 on the light panel, under the 3:1 WCAG 1.4.11 requires of
  a non-text indicator. `--fe-insert-text` already carried the per-theme value.
- `snapping.ts` set a swatch border to the themed `OVERLAY.swatchBorder` on
  construction, then **overwrote** it with raw `rgba(255,255,255,0.3)` on
  `mouseleave` — so hovering a swatch once left it permanently borderless on
  the light panel. A state bug, not only a theming one.

A third variant was found by code review and is the one worth remembering,
because the audit itself introduced it. `measure-overlay.ts` and
`multi-select.ts` had been switched from a fixed `#3b82f6` to the **themed**
`OVERLAY.info` — the inverse mistake. Both draw on the page, so the same
measurement rendered in a different colour depending on a panel setting, and
the distance label (white on the frame colour) fell from 3.68:1 to 2.54:1 in
dark mode. Each element also ended up with a themed border over a fixed
translucent fill. Fixed by adding `MEASURE_INDICATOR` to `shared/constants.ts`
as an explicit on-page constant, with the label on `#1d4ed8` (6.7:1 with
white) rather than on the frame colour.

The lesson for the next audit: "theme the colour" is not the rule. The rule is
that panel chrome is themed and on-page indicators are fixed, and a mechanical
sweep can break it in **both** directions.

`BOX_MODEL` was examined and deliberately left alone. Its text roles are
themed while its fills are raw `rgba(…, 0.20)`, which looks half-finished but
is correct: translucent fills composite over the themed panel background and
adapt on their own, whereas opaque text cannot.

**SDK bump and the advisory.** `@modelcontextprotocol/sdk` `^1.25.2` →
`^1.32.0`, folded into this branch for the critical `proxy-addr` advisory
(GHSA-jqcg-44mw-7w3h). It reaches consumers through SDK → express, so it is
not dev-only.

The bump alone did **not** clear it, which is what this session initially
assumed and the security sign-off caught. The SDK moved to 1.32.2, but
`express@5.2.1` still resolved `proxy-addr@2.0.7`, inside the vulnerable
`>=1.1.0 <2.0.8` range — a transitive pin a direct-dependency bump does not
move. `npm audit fix` was needed on top, and now resolves 2.0.8. Prod-path
advisories went from 6 to 1.

The one left is `zod` (GHSA-mrhx-c7xc-m3w5, high, memory exhaustion on
oversized collections). It is **not fixable from here**: the fix is zod 4.6.7,
a major bump, and `@modelcontextprotocol/sdk@1.32.2` pins zod 3.x — so
`npm audit fix --force` would break the SDK rather than patch it. It waits on
upstream SDK support for zod 4. Exposure is limited: the MCP server binds to
localhost and the advisory needs an attacker-supplied oversized payload.

- Critic dispatched in combined mode from the `review` phase: both sections

  1280×800, no alpha

  `#D2F2CB` on `#2F2F2F` is 11.03:1 both ways

  project memory claiming no release existed was stale.
- Security and code review both withheld sign-off on the first pass and both
  were right — see above. Neither defect would have been caught by `tsc`, the
  build or the test suite, all of which were green throughout.

## Notes for next session

Two governance failures cost time and are worth recording. A critic verdict
was dropped twice: first because the dispatch prompt dictated a
`COHESION_VERDICT:` line instead of the contracted `GATE_RESULT:`, and second
because the critic was dispatched from `build` when the contract expects
`review`. The reason for the second was written to
`.claude/.automation/escalations/` as `reason=phase_mismatch`, which went
unread for two attempts. **Check that directory first when a verdict does not
persist** — it states the cause rather than requiring it to be inferred.
