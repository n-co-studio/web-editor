## Goal
Brief 1 of the `breakpoint-awareness` task group. Make the human-readable Markdown produced by the copy-prompt feature carry breakpoint context (`diff.context.breakpoint`, `breakpointValue`, and `source.mediaQuery`) so the receiving AI knows which viewport / media-query the edits target. Session 147 carried this provenance through to the MCP server but deliberately left the clipboard Markdown alone; this brief closes that gap. The brief also produces a `formatSourceContext()` helper for Brief 2 to reuse.

## Changes Made
- `packages/chrome-extension/src/content/batching/prompt-serializer.ts` — Added three helpers and integrated them into the existing render loop:
  - `formatBreakpointHeading(context)` — appends `— @ <breakpoint> (<breakpointValue>)`, `— @ <breakpointValue>`, or `— @ <breakpoint>` to the element heading (all four field combinations handled symmetrically).
  - `formatSourceContext(source, activeBreakpointValue)` — exported helper that emits ` [@ <source.mediaQuery>]` only when the source rule's media query diverges from the active breakpoint value. Comparison normaliser is heuristic (strip whitespace + lowercase) — an accepted limitation, since token-resolved values (e.g. `768px`) cannot match raw conditionText (e.g. `(min-width: 768px)`).
  - `hasResponsiveContext(diffs)` — pre-pass that returns true when any diff has breakpoint metadata on its context or `source.mediaQuery` on any property change; gates a blockquote instruction line under the existing header.
- `packages/chrome-extension/src/content/batching/prompt-serializer.test.ts` — New colocated test file. 12 unit tests across two suites: six cases for the serializer (heading both/value-only/token-only/none, per-property suppressed/divergent, near-match heuristic, raw-JSON round-trip) and five for the exported helper (undefined source, no mediaQuery, normalised match, divergence, undefined active breakpoint).
- `packages/chrome-extension/scripts/run-tests.mjs` — New lightweight test runner. Walks `src/**/*.test.ts`, bundles each with esbuild (already a dev-dep), and runs the bundles via Node's built-in `--test` flag. Zero new dependencies.
- `packages/chrome-extension/package.json` — Added `test` script wiring up the runner.
- `packages/chrome-extension/tsconfig.json` — Added `"exclude": ["src/**/*.test.ts"]` so `tsc --noEmit` doesn't require `@types/node` for the test imports.
- `docs/ai/task-groups/breakpoint-awareness.yaml` — New task group contract. Documents the two-brief sequential group, the `formatSourceContext` integration point, conventions, and per-brief governance evidence.

## Follow-ups for Brief 2
- Brief 2 reuses the exported `formatSourceContext(source, activeBreakpointValue)` helper. Signature is stable. JSDoc documents the parameter semantics explicitly: `activeBreakpointValue` is `PageContext.breakpointValue` (the resolved value), not `PageContext.breakpoint` (the token name).
- The heuristic normaliser (strip whitespace + lowercase) does not match token-resolved values against raw CSSOM conditionText. This is an accepted limitation per the brief; if Brief 2 needs stricter media-query matching, that work is in-scope for the consumer, not a regression here.
- Reorder-only or insert-only diffs (no `PropertyChange` entries) do not currently contribute to the responsive-context blockquote via the per-change path; the `context.breakpoint`/`breakpointValue` path still fires. Out of scope for Brief 1; flag for Brief 2 if structural-change breakpoint annotations become a requirement.
