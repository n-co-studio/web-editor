## Brief
Fix editor drag/reorder UX — overlay containment + universal reorder affordance (issue #30).

Two bugs in the content-script drag editors:
1. **Containment** — an in-overlay reparent drag could drop into a page-root
   container *outside* the active overlay, reparenting the element out of the modal.
2. **Reorder affordance** — full-width items in a wrapped gallery were denied the
   reorder tool (the `flexWrap !== 'nowrap'` block), so an in-list move fell back to
   a reparent.

## Diagnosis (step 1 — root cause first)
The full-width and narrow gallery items **share the reorderable parent** (a wrapping
flex/grid container). The disabling condition was the `flexWrap !== 'nowrap'` guard in
`getReorderBlockReason` — not a separate-container problem. The fix branch is therefore:
relax that guard **and** add gated 2D gap-math (a wrapped container hit-tested on a
single projected axis picks the wrong gap). The `examples/demo-app` fixture reproduces
this locally.

## Summary
Contained in-overlay reparent drags to the active overlay and exposed the reorder
affordance for every sibling in a wrapped/2D reorderable container.

- **Overlay containment (Bug 1):** new `findOverlayRoot(el)` (heuristic: `<dialog>`/
  `:modal` → `[aria-modal]`/`[role=dialog]`/`[role=alertdialog]` → nearest positioned
  high-`z-index` non-full-viewport ancestor → `document.body` fallback; never throws).
  `discoverTargetContainers` gains a `scopeRoot` param and filters candidates to the
  overlay. A drop with no in-scope target is a no-op — the element snaps back to origin
  and **no diff is enqueued** (protects the #27/#28/#29 uid/anchor identity contract).
  A `not-allowed` cursor signals the invalid-drop state during drag.
- **Same-container → reorder (Bug 1 correctness):** a same-container drop via the
  reparent tool now commits a `ReorderChange` (`fromIndex`→`toIndex`), not a
  `ReparentChange`. The DOM move uses reorder semantics (`commitReorderInPlace`,
  mirroring `ReorderEditor.commitReorder`) so the moved node lands exactly where the
  emitted diff describes — this also fixes a latent off-by-one in the old same-container
  reparent path.
- **Reorder affordance (Bug 2):** removed the `flexWrap !== 'nowrap'` block; only a
  non-layout parent or a single child now disable reorder.
- **Gated 2D gap-math (Bug 2):** `detectWrapping` gates a 2D nearest-gap path
  (`computeGapZones2D` leading-edge model + `hitTestGapZone2D` Euclidean distance).
  Gated to wrapping flex / multi-line grid only — the `nowrap` single-axis path
  (`computeGapZones`/`hitTestGapZone`) is byte-for-byte unchanged (zero regression).
  Wrap-aware drop indicators render as pips at gap centers; single-axis keeps lines.
- **`containerDirection` wrap fix:** `computeContainerDirection` appends a ` wrap`
  suffix (e.g. `row wrap`) for wrapped/2D containers. Additive — the first token stays
  `row`/`column`, so existing consumers are unaffected. No `WS_PROTOCOL_VERSION` bump.
