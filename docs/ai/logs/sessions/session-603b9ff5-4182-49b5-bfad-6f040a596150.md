# Brief 5 — WebSocket handshake hardening (HACK-008)

## Identity
- **Branch:** fix/ws-handshake-hardening (from main after Brief 4) · **Date:** 2026-07-17 · **Mode:** auto · **Solo:** true · Same session (603b9ff5).
- Originally handed off as a brief; operator asked to take it on directly ("take care of the open tails").

## Design decision (operator-selected)
HACK-008 turned out to have a real security/compat fork. Operator chose the **backward-compatible probe** over dropping old-server compat or deferring. Verified enabler: the server's `handleStatusRequest` answers an identifier-free `STATUS_REQUEST` with no prior registration, so a new extension can probe an old server.

## Scope (3 files, +127/−20, high-risk)
- `content/websocket-client.ts`: `handleOpen` no longer sends `EXTENSION_HELLO` on open — it sends an identifier-free `STATUS_REQUEST` probe + arms a handshake timer. New `confirmHandshake()` (on first valid MCP identification → status connected, sends `EXTENSION_HELLO` with tabId/pendingDiffIds, starts keepalive) and `isMcpIdentification()` (SERVER_HELLO w/ string protocolVersion, or STATUS_RESPONSE w/ numeric counts). `handleMessage` ignores unconfirmed-peer traffic except identification (consumed, not double-processed); envelope now rejects null payloads. Close handler branches: unconfirmed → `scanPorts(port+1)`, confirmed drop → `scheduleRetry()`. `sendDiffBatch`/`sendStatusRequest` gated on confirmation. New `WS_HANDSHAKE_TIMEOUT_MS = 2_000`.
- `mcp-server/bridge.ts`: `handleConnection` sends `SERVER_HELLO` proactively on connect (old extensions ignore it and speak first).

Skew coverage: new/new (proactive SERVER_HELLO confirms), new/old (STATUS_RESPONSE to probe confirms — no server change needed), old/new (old ext speaks first, works), old/old (unchanged).

## Accepted residual (operator-approved, documented in code)
Without a shared secret, a foreign process that *speaks* the MCP protocol can spoof an identification and still receive the identifiers (tabId + diff UUIDs — no secrets/PII). Reordering only defends against non-protocol squatters. Full closure = the deferred shared-secret handshake (which a content script can't trivially obtain — its own design problem).

- Critic (combined): APPROVED (0 critical; verified no double `onServerHello`, listener-before-probe ordering, timer lifecycle, all skew combos). Two recs folded in: null-payload envelope guard + `sendStatusRequest` confirmation gate.
