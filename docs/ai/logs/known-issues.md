| Symptom | Root Cause | Fix | Session |
|---------|-----------|-----|---------|
| Stop hook blocks session close even after session log was committed | Hook only checked `git diff` (uncommitted changes); committed updates were invisible. Initial fix used `pipe \| grep -q` which failed due to SIGPIPE (exit 141) — `grep -q` closes pipe early, `git log` gets SIGPIPE, `pipefail` returns 141 | Replaced `pipe \| grep -q .` with variable capture (`$()`) and `[ -n ]` test. Also added `git log --since="4 hours ago"` for committed changes | Session 3 |
| Stop hook blocks again after first block, even though session log was updated | When hook blocks (exit 2) and agent updates session log, the hook still runs its exit path (line 119) which writes the new hash as baseline. On next stop attempt, current hash matches the just-stored baseline → hook thinks nothing changed and blocks again | Extracted `update_baseline()` function called from all early-exit paths (`stop_hook_active`, `SKIP_SESSION_LOG`, zero-change). Blocking exit (exit 2) never updates baseline. Moved path/function definitions above guards so hash update is available in all exit paths | Session 13, fixed Session 15 |
| Stop hook blocks exit on zero-change sessions (no commits, no file edits) | Hook unconditionally requires a modification to `session-log.md` — it has no concept of session "weight." A read-only orientation or Q&A session triggers the same block as a multi-commit feature build | Added session weight detection: checks `git diff` (uncommitted), `git diff --cached` (staged), and `git log $BASELINE_SHA..HEAD` (commits since last session close). Zero-change sessions downgrade to advisory. Uses stored baseline commit SHA instead of hardcoded time window. Governance docs updated (AI.md, workflow.md, Decision 0004) | Session 14, fixed Session 15 |
| Template sync fails: "Repository not found" pulling from private template repo | Default `GITHUB_TOKEN` cannot access a different private repo. Fine-grained PATs incompatible with git clone in Actions. `actions/checkout` persists `GITHUB_TOKEN` as extraheader overriding PAT. After `persist-credentials: false`, push fails without explicit target token. `GITHUB_TOKEN` cannot push workflow file changes | Classic PAT (`repo` + `read:org`), `persist-credentials: false` on checkout, `source_gh_token` for pull, `target_gh_token` for push, `.templatesyncignore` excludes workflow file, enable "Allow GitHub Actions to create PRs" in repo settings | Session 16 |
