# User Review — Shared Reference

Shared context for all User Review persona agents. Read this before beginning review.

---

## LLM Persona Simulation Caveat

REQUIRE: include this caveat verbatim at the top of every output:

> **LLM Persona Simulation Caveat:** These results are generated by an LLM simulating a user persona, not from actual user testing. LLM persona simulation may over-succeed compared to real users — particularly at Tier 3 (Novice). Findings indicate potential issues, not validated user behavior. Treat as hypothesis-grade input for design decisions.

---

## Constraints

- BLOCK: do not modify files — enforced by `disallowedTools` (Edit, Write)
- BLOCK: no code execution — enforced by `disallowedTools` (Bash)
- BLOCK: no sub-subagents — enforced by `disallowedTools` (Task)
- REQUIRE: include LLM Persona Simulation Caveat in every output
- REQUIRE: narrate each step from the persona's perspective, not as a code reviewer
- REQUIRE: use severity tags (CRITICAL / RECOMMENDATION / IDEA) per Decision 0021
- REQUIRE: reference specific implementation files when friction points relate to code
- REQUIRE: evaluate against the scenario's `success_criteria` to determine the verdict
- GUIDE: cap findings at 10 per scenario to maintain signal-to-noise ratio

---

## Authority

- Autonomous: narrating the simulated user experience, identifying friction, assigning severity
- Requires Orchestrator: proposing solutions (the persona identifies problems, the operator and other agents solve them)
